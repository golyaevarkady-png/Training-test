# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Marlowe & Finch ops-dashboard: a Spring Boot 3.2 / Java 17 read-only JSON API under `/api`, plus a plain-JavaScript page in `src/main/resources/static/` (no build step, no framework, charts are inline SVG). The repo also holds the "Claude Code, zero to expert" workshop material in `workshop/` and `docs/` (tickets are in `docs/tickets/`).

## Commands

```bash
./mvnw test                                              # Java suite (JUnit 5, H2, MockMvc)
./mvnw test -Dtest=DashboardRepositoryTest               # one class
./mvnw test -Dtest='DashboardRepositoryTest#vendorsAreSoonestContractEndFirstWithDaysUntilFromTheFixedClock'
npm ci && npm test                                       # frontend suite (Jest + jsdom)
npx jest src/test/javascript/render.test.js -t 'warn class'   # one file / one test name
SPRING_PROFILES_ACTIVE=demo ./mvnw spring-boot:run       # run on in-memory H2, no Docker
docker compose up -d db && ./mvnw spring-boot:run        # run on PostgreSQL 16 (default profile)
python3 tools/make_seed.py                               # regenerate V2__seed.sql, docs/data CSV and the git-ignored ANSWER-KEY.md
```

There is no linter or formatter configured.

## Rules

- `pom.xml` dependencies are frozen. Any change needs a CHG ticket.
- "Today" is pinned to 2026-09-21 (`ops.today` in `application.properties`, the `Clock` bean in `ClockConfig`). Use the injected `Clock` (`LocalDate.now(clock)`), never the system clock; the seed data, default ranges and test expectations all depend on it. Frontend "today" comes from `/api/health`, not the browser clock.

## Architecture

- **Backend:** controllers -> two repositories (`DashboardRepository`, `VendorRepository`) using plain SQL via Spring JDBC (no JPA) -> Java records as response bodies. `DateRange` resolves `from`/`to` defaults (last 30 days ending today) and does no validation yet (TODO-232; `DashboardControllerTest.malformedFromCurrentlyProducesA5xx` pins the current 500 behaviour).
- **Database:** Flyway migrations `V1__schema.sql` (schema) and `V2__seed.sql` (generated by `tools/make_seed.py`, deterministic; do not hand-edit). Profile `postgres` is the default (`DATABASE_URL`/`DATABASE_USER`/`DATABASE_PASSWORD` override); profile `demo` uses H2 in PostgreSQL mode, so SQL must work on both.
- **Frontend:** `app.js` is one IIFE; everything goes through `initApp(document, fetchImpl)`. In the browser it auto-starts with `window.fetch`; under Node it exports `initApp` and the pure helpers (`formatRate`, `formatMoney`, `barWidths`, `applyPreset`, `daysUntil`) for tests.

## Tests

- **Java:** every test class is `@SpringBootTest` + `@ActiveProfiles("demo")`, so it boots the whole app on H2 with the real migrations and asserts against the real seed numbers. No Docker needed.
- **Jest:** `src/test/javascript/setup/loadApp.js` is the harness. `loadApp(overrides)` mounts the `<body>` of the real `index.html` into jsdom, swaps `fetch` for an in-memory fake API serving `FIXTURES` (override per test, or `failing: ['/api/...']` for 500s; calls are recorded in `api.calls`), re-requires `app.js` and awaits `app.ready`.
- **When adding an element `id` to `index.html`, add it to `REGISTERED_IDS` in `loadApp.js`**; `harness.test.js` fails otherwise.
- The fixtures mirror the Java response records; if an API shape changes, update `FIXTURES` too.

## Database access (MCP)

`.mcp.json` registers a read-only `postgres` MCP server at `postgresql://ops:ops@localhost:5432/ops`. It only has data once the app has started against that database (Flyway seeds it). Without a database, `docs/data/deliveries-last-30-days.csv` answers the same questions.
